# Changelog

## 0.6.30 - 2026-11-07

- **Rows no longer get a full background fill.** A task row used to paint its whole block violet (and red when a step failed), which tinted every line inside it. Now only the left bar and the label keep the colour, so the timeline stays on your editor's background.
- **Files with spaces in their path open again.** A reference like `docs/Bản giao.md` or `tài liệu/H S K K/bản giao 2026.md:12` was rejected as "not a path", so clicking it did nothing — this is the "cannot open the .md file" report. Paths with spaces now open (still rejected when the text is a sentence, not a path).
- **Artifacts can open in your real browser.** New "Open in browser" button on every artifact card, plus a fourth value for `locaithAgent.artifacts.autoOpen`: `browser` writes the page (fonts embedded) and opens it in Chrome/Edge instead of a VS Code side tab.
- **Compaction threshold is now yours to set.** `locaithAgent.agent.compactAtPercent` (50–95, default 80) replaces the hardcoded 80%: on a large-window model, compacting at ~100k was making the assistant forget the job. The value is clamped and passed to every compaction path.

## 0.6.29 - 2026-11-07

- **Ask before the work, never after it.** `offer_options` changed meaning: it is now the one clarification you get when the request is genuinely ambiguous — the assistant reasons first (is this enough to finish end to end?), and only when two plausible readings would produce different deliverables does it show 2–4 readings as buttons and STOP. Clicking one starts a run that finishes that whole version of the job.
- **A finished job is reported as finished.** No "what next?" buttons, no menu of optional extras, no next-steps list: a menu after the work is just a suggestion in a different shape. The prompt says this explicitly, and the option row no longer appears on a completed turn.
- **Deterministic guard:** if the model already wrote files in a run and then tries to ask which direction to take, the call is blocked with a message telling it to finish and verify instead — so "do everything, then ask" cannot come back.
- The ask itself leaves no clutter in the timeline: the buttons are the interface, so the tool row is hidden.
- **Loop budget raised to 200 turns by default** (was 60), and the setting now goes up to 1000. Claude Code has no practical cap; 200 runs any real job end to end, and on hitting the limit the assistant still gets one wrap-up turn instead of stopping mid-task. Lower it only if you want to cap cost.

## 0.6.28 - 2026-11-07

- **The whole process now collapses into ONE line — and nothing is lost.** While a turn is running, every tool call, command, test run, thinking block, status line, task update and file edit in a stretch sits in a single row ("34 actions · 7 files changed · 2 failed"), with the live "reading src/a.ts" hint on the same line. Click it and the full, unaltered sequence opens; a "Collapse" row at the bottom closes it without scrolling back up. Text, artifacts and errors still split the run, so nothing is reordered.
- **Numbers are colour-coded.** Actions stay neutral, "N files changed" is green, failures are red — and a run with any failure gets a red left edge and a red icon, so a bad run is visible at a glance instead of hiding in grey.
- **No more trailing ellipses on live labels.** "Working…" and "Thinking · 3 parts…" became "Working" and "Thinking · 3 parts": the spinner already says it is live, the dots only added noise.

## 0.6.27 - 2026-11-07

- **Memory is now always in context — for every model, not just Locaith.** The persistent memory index (`.locaith/memory/MEMORY.md` for the project, `~/.locaith/memory/MEMORY.md` for you) is re-read from disk on every turn and injected as a `<memory>` block, so it survives any number of compactions and does not depend on the model deciding to call a tool. A new `remember` tool writes one dated line (`user` / `feedback` / `project` / `reference`), refuses secrets, skips duplicates, and works across providers; the `ghi-nho-memory` skill is no longer limited to Locaith models.
- **Collapse at the bottom, not only at the top.** Opening a group (the work summary, a command or edit group, a tool body, a thinking block, the task group) now puts a "Collapse" row right under the content, so you close it where you are instead of scrolling back to the header.
## 0.6.26 - 2026-11-07

- **A request now runs to the end, and "done" has to be proven.** The engine gained a completion gate instead of a reminder: while the task list still has unfinished work it names the remaining items and keeps going (at most twice), and a run that edited files without running anything that can fail is sent back to run the real check (tests / typecheck / build / the product) before it may report success. It never fires after you press Stop and never loops forever.
- **Old conversations pick up the new version immediately — no new session needed.** Sessions are upgraded when they are read: missing fields get today's defaults, legacy `thinkingLevel: "swarm"` becomes the swarm flag plus `max`, synthetic nudges written by older builds are dropped, and when the stored `appVersion` differs the prompt fingerprint is cleared so stale signed thinking is not replayed under the new prompt. A short notice says the conversation was upgraded.
- **Options are buttons now, not a "next steps" paragraph.** The agent calls `offer_options` with 2–4 self-contained choices; they render under the conversation, and clicking one sends that instruction and does the whole job. The prompt forbids closing a reply with a prose list of next steps. The "remaining steps" panel is collapsed to one line by default — open it only if you want to pick a step.
- **The plan survives compaction.** The live task list is re-attached to the summary on every compaction, so a long run does not forget what is left after the context is trimmed.
- **Default loop budget 30 → 60 turns**, so a multi-part request finishes in one run instead of stopping to be restarted.
## 0.6.21 - 2026-11-06

- **The full answer is never hidden behind "Worked for" again.** A finished turn collapsed everything before its *last* text block, so a short closing line stayed visible while the whole answer above it went into the collapsed summary. The answer region is now the whole trailing run of text: everything before it still folds into the turn summary, the answer never does.
- **Expanded groups no longer break on a narrow pane.** Opening a task, command or edit group put its body as a column beside the header, so around 400 px the body shrank to one character per line. Group bodies now stack under their header at every width.
- **Task rows carry their state.** A task row with a failed step turns red — border, background and label — instead of leaving the word "Error" in the same grey as the rest of the meta.
- **The agent panel opens in the centre of the screen.** It used to sit on the bottom edge, so reaching it meant leaving the chip, and leaving the chip closed it. It now opens centred, waits 260 ms before closing, and each row shows what that agent is working on, with the full detail on hover.
- **Consecutive thinking blocks are grouped.** Six "Thinking · 517 tokens" rows in a row became one "Thinking · 6 parts" row; expanding it keeps every part, numbered.

## 0.6.19 - 2026-11-06

## 0.6.18 - 2026-11-06

## 0.6.5 - 2026-11-05

- **Remote: open your machine from your phone with nothing to pair.** Sign in to locaith.ai with the same account, open *Remote VS Code* and pick the machine — or type **/remote** in the chat: no pairing code, no link or QR to copy, no “Allow” dialog. The machine keeps a random 128-bit *account key*, lists it in your Locaith account's machine list (you can read it back only while signed in to that account), and the page uses it to open the usual end-to-end encrypted session. Nothing else changed: the same allowed commands, “Bypass all prompts” still cannot be switched on from a remote page unless `locaithAgent.remote.allowBypass` is on, and the relay still sees only ciphertext.
- **What you are trusting.** With this on (the default), anyone who can sign in to your Locaith account can control the machines that have it on — they read the key from your account — so protect the account with a strong password. The first time it becomes active on a machine, VS Code shows a one-time notice with a **Turn it off** button, and a line appears in the chat each time a browser opens a session. **Remote: paired devices → Change the account key** cuts every browser that is in right now; a browser still signed in to your account fetches the new key and comes back, so to lock someone out turn the Remote switch off and change your password. Turn the whole thing off with `locaithAgent.remote.trustAccount` = false: Remote goes back to pairing each device with a link/QR and **Allow**. Turning it off (or turning Remote off, or signing out) also deletes the key from your account.
- **Pairing by link/QR is still there** (*Remote: pair a new device*) for a browser that is not signed in to your account, devices you already paired keep working, and `/remote` falls back to the pairing link by itself when the machine list cannot be reached or the Locaith server has not been updated yet. The chat's Remote card now offers **Open the Remote page** instead of **Pair a new device** while the account key is in use.
- **Hardening from an independent security review, fixed before release.** The account key is now tied to the account that created it and is deleted when you turn Remote off, turn the Internet path off, sign out, or sign in as someone else (closing VS Code keeps it, so open browser tabs reconnect); *Change the account key* now publishes the new key BEFORE it cuts the old sessions (cutting first could leave a browser stuck on the old key); a recorded `hello` can no longer be replayed after a few minutes (hello nonces are now remembered by count, not by time, and two identical hellos arriving together open one session); the “a browser opened this machine” notice fires only for a real session and is kept and shown when you open the chat panel again if it was hidden; ending a remote session no longer leaves a connection counted on the machine; and `/mode bypass` typed as a message from a remote device can no longer slip past `locaithAgent.remote.allowBypass` (that loophole has existed since 0.5.2). On locaith.ai: an account session ends when you sign out or switch account in another tab, a stale key repairs itself, and the browser store refuses account records.
- **Known limits, written down in `docs/REMOTE-RELAY.md`:** anything that runs in the locaith.ai page can read the account keys of all your machines (the site loads Tailwind from a CDN and has no content-security policy yet), and a stolen extension device token can add a fake machine to your list (it cannot read keys; the page only opens a machine by itself if you already opened that same machine in this browser — a new one needs your click on **Open**) — sign that device out on locaith.ai.
- **A limit that could be exceeded is now enforced.** The cap on simultaneous sessions per device (5, and 10 for the new account sessions) was checked a few milliseconds before a session was registered, so several browsers connecting at the very same moment could all slip past it. It is now checked right before registration.
- Internal: `ACCOUNT_DEV` / `deriveAccountKey` in `e2e.ts` (K_dev = HKDF-SHA256(account key, salt = empty, info = lp("account_dev", hostId)); shared fixture vector, web copy byte-identical); `RelayHost` options `accountKey` / `onAccountSession` and `closeAccountSessions()`; `AccountClient.hostUpsert(…, accountKey)` (`''` clears the key, omitted keeps it; retries without the key on a server that does not know it); `RemoteService.rotateAccountKey()`, `openWeb()` now returns how it opened (`account` / `pairing` / `local` / `none`); `ChatController.notifyLocal()`; message `remote_open`; `RemoteView.trust`; setting `locaithAgent.remote.trustAccount`; Locaith server migration `20261105_remote_account_trust.sql` (column `account_psk`, new `ext_host_upsert` parameter, `ext_hosts_list` returns the key to its owner) — apply it before relying on the feature. See `docs/REMOTE-RELAY.md` §2b.

## 0.6.4 - 2026-11-05

- **Chrome pages the extension can never control no longer make the assistant retry.** When the assistant tried to drive the Chrome Web Store or a `chrome://` / `edge://` page, the `chrome` tool passed Chrome's bare English error (*"The extensions gallery cannot be scripted."*) straight through, and the model tried again. It now says plainly that this is a limit of Chrome, not a temporary error, and tells the assistant to stop and ask you to do it yourself. Errors you CAN fix — a missing site permission, a page that failed to load, a closed tab — keep their original message.
- **A command that times out with no output now explains itself.** When `run_command` ran out of time without printing anything, it only said *"Command stopped after N seconds"*. It now adds that the shell may have started slowly (on some machines Windows PowerShell sometimes needs a minute or more to start) or that the command prints nothing until it finishes, and asks the assistant to retry ONCE with a longer `timeout_seconds` (120 or more) before deciding the command hung. Commands that did print something keep the old message.
- Both came from reading the error logs of Locaith-v5-flash / SI (4–5 Nov 2026): the Chrome error happened twice, and 9 of the 10 timed-out commands had printed nothing. The hint reduces the damage; it does not remove the cause of a slow shell start, which is still unexplained. If it keeps happening on your machine, `locaithAgent.terminal.shell` lets you pick another shell (`pwsh` or `cmd`).
- Internal: `friendlyChromeError()` in `src/core/chrome/tools.ts` (only three Chrome messages count as a hard limit); the hint in `src/core/tools/terminal.ts`; tests in `test/loiLocaithV5.test.ts`. Nothing else changed.
